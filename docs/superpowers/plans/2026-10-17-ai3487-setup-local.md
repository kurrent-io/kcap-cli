# `kcap setup --local` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A third `kcap setup` arm that installs the local-edition stack on a fresh Mac all-or-nothing, commits it
as the active profile's server, and continues with the existing harness, daemon and import steps; plus a `--json`
mode for the desktop wizard.

**Architecture:** An install core (`LocalInstaller`) in `src/Capacitor.Cli/LocalEdition/` runs under the existing
lifecycle lease. It reports typed events and is recovered by a `setup` `ILifecycleRecovery`. Two renderers in
`src/Capacitor.Cli/Commands/` drive it: the terminal setup arm and JSON lines. Durability, root identity and the
per-user unit lock are small Core/Cli primitives the core composes.

**Tech Stack:** .NET 10 NativeAOT, TUnit, System.Formats.Tar, ECDSA P-256 (existing `LocalBundleManifestKey`),
source-generated System.Text.Json.

**Spec:** `docs/superpowers/specs/2026-10-17-ai3487-setup-local-design.md`. Read it before any task; its section
names are cited below.

## Global Constraints

- Journal wire values: `server_start` is exactly `"allow"`, `"fenced"` or `"deny"`. Setup phases are `pending`,
  `unit`, `committing`, `allowed`, and the operation is `"setup"`.
- Pre-commit calls to the local server: only `GET /healthz/ready` and `GET /auth/config`. The header is
  `Kcap-Installation: pending`. The body for None is `{"provider":"None",...}`.
- Bundle URLs: `<base>/<rid>/kcap-local-<version>-<rid>.{json,json.sig,tar.gz}`. The default base is
  `https://www.kurrent.io/download/local`. The overrides are `KCAP_LOCAL_BUNDLE_BASE_URL` and
  `KCAP_LOCAL_BUNDLE_VERSION`. Only signed manifests are accepted.
- Flags: `--local`, `--single-user`, `--yes`, `--json`.
- Socket limits: 103 bytes on macOS, 107 on Linux, measured on `<root>/run/.s.PGSQL.5432` and
  `<root>/run/kurrentdb.sock`.
- Default port 9473. The unit lock is `~/.config/kcap/local-unit.lock`.
- JSON lines carry `"v": 1` and `"event"`, in snake_case. The failure codes are exactly the spec's "Events" list,
  plus `leftover_state` and `config_unreadable`.
- Exit codes: 0 committed, 1 failed, 130 when an interrupt was received.
- Code comments follow CLAUDE.md "Comments": scarce, no history, no spec coordinates.
- Commit subjects are imperative, at most 80 characters, with no issue reference (AI-3487 has no GitHub twin). Each
  ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- AOT: no reflection JSON, and `new JsonArray(...)` rather than collection expressions. After Task 15, run
  `dotnet publish src/Capacitor.Cli/Capacitor.Cli.csproj -c Release 2>&1 | grep -E 'IL[23][01][0-9]{2}'`, which must
  print nothing.
- Tests: `TempDir`/`TempHome`/`TempConfigRoot` injection and `tmp.CreateExecutable` for anything run; no
  `Console.SetOut`; env vars through `EnvScope`.
- Run one class: `dotnet run --project <test csproj> -- --treenode-filter "/*/*/<ClassName>/*"`.

## Review Focus

1. **A home path with spaces or non-ASCII characters:** the socket check counts UTF-8 bytes, and the plist and env
   carry the path verbatim. → Task 9 test `Socket_length_counts_utf8_bytes`.
2. **A dev build whose version has `+metadata` or no published bundle:** the version is `CurrentDisplay()`, and a
   404 says `bundle_not_published`, naming both overrides. → Task 7 test `A_missing_manifest_names_the_overrides`.
3. **Re-running `kcap setup --local` after success:** no download, the same port, and exit 0 with no questions. →
   Task 13 test `Reuse_downloads_nothing_and_asks_nothing`.
4. **Ctrl+C during the ten-minute readiness wait:** a rollback that unloads the unit before deleting anything. →
   Task 11 test `Cancel_during_readiness_unloads_before_deleting`.
5. **Port 9473 taken by an unrelated process:** another port is chosen and never a retired one. → Task 10 test
   `A_busy_default_port_falls_back_to_a_free_non_retired_one`.

### Task 8: Bundle unpacker

**Files:**
- Create: `src/Capacitor.Cli/LocalEdition/LocalBundleUnpacker.cs`
- Test: `test/Capacitor.Cli.Tests.Unit/LocalEdition/LocalBundleUnpackerTests.cs`

**Interfaces:**
- Produces: `static Task LocalBundleUnpacker.UnpackAsync(string archive, string destination, CancellationToken ct)`.
  - It reads the gzip stream with a `TarReader` loop of its own.
  - Names are normalized by stripping a leading `./`, and `.` is skipped. A rooted name or a `..` component is
    refused.
  - Each entry type is handled as follows:

    | Entry | Handling |
    | -- | -- |
    | Directory | Created, mode 0700 |
    | RegularFile / V7RegularFile | Written with `CreateNew`, mode = entry mode & 0700 \| `UserRead`, flushed to disk |
    | SymbolicLink | The target resolved against the link's directory must stay inside `destination`; then `File.CreateSymbolicLink` |
    | HardLink | The target must be an earlier regular-file entry; it is copied |
    | Anything else | Refused |

  - Every directory is synced after its entries are written.
  - The tree root must end with an executable regular file `kcap-server`.
  - Failures throw `LocalBundleException(VerificationFailed, "<entry>: <reason>")`.
