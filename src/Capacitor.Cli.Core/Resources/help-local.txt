kcap local — Run the local installation that `kcap setup --local` made

Usage: kcap local <subcommand> [options]

Subcommands:
  status                    Explain the installation's state: version, port, service, search, each store, what to do.
                            Names a stopped, changing, uninstalled, purged or port-blocked server apart
                            (a port another program answers on is blocked, even when the OS cannot name it)
                            and suggests start only when a start can bring it up
  start                     Start the server and wait until it is ready
  stop                      Stop the server and wait until nothing of it is left; it stays stopped until start
  restart                   Stop, then start
  logs [-n|--lines N]       Print the last N lines (default 50) of each log: the server's, which carries
                            Postgres's and KurrentDB's output too, and its startup output when it has any
  open                      Open the web UI in a browser
  upgrade [--json] [--if-installed]
                            Move the stack forward to this kcap's version. A kcap at or below the
                            stack's version changes nothing. Forward-only: a failure before the
                            switch starts the old version again; after it, the new version stays
                            selected and stopped, and kcap local start tries again.
      --json                One JSON object per line on stdout, for the desktop app.
      --if-installed        Print nothing when there is no installation.
  fetch [--json]            Download and verify this kcap's server bundle into the cache under the
                            installation's root, so the next `kcap setup --local` installs it without
                            downloading. Installs nothing; the cache is emptied once an install uses it.
      --json                One JSON object per line on stdout, for the desktop app.
  intelligence <answer> [--model <model>] [--import-outcomes | --no-import-outcomes] [--json]
                            Choose who runs the server's background model calls: titles, outcomes, evals.
                            <answer> is claude or codex (your own agent, run by this machine's daemon),
                            anthropic, openai, openrouter or cohere (a provider, with your API key), or none.
                            A provider's key is read from its variable (ANTHROPIC_API_KEY, OPENAI_API_KEY,
                            OPENROUTER_API_KEY, COHERE_API_KEY) or asked for, never taken from the command
                            line; the server tries it once before storing anything.
      --model <model>       A provider's model. Without it the server's default runs (gpt-5-mini for OpenAI).
      --import-outcomes     Imported sessions also get a summary of what each achieved, at the server's daily
                            pace for background work on imports. --no-import-outcomes turns that off.
      --json                One JSON object on stdout, for the desktop app.
  uninstall [--purge] [--force] [--yes] [--quick]
                            Stop every kcap daemon and watcher and the local server, then remove the
                            server's service and binaries. Its data and identity are kept, so
                            `kcap setup --local` brings it back on the same URL.
      --purge               Also delete its data, logs, downloaded models, pending recordings and
                            caches, and clear every profile pointing at it. Its URL is retired: nothing is sent to it again,
                            and a new installation gets a new port.
      --force               Uninstall even while a daemon is running agents; they end with it.
      --yes, -y             Do not ask for confirmation.
      --quick               Windows only. Give the server about 8 seconds to stop, then remove its
                            service whether or not it has finished, for an app uninstaller with a deadline.
                            Files a server still stopping holds open stay behind. Cannot be
                            combined with --purge.
  help                      Show this help

status exits 0 only when the server is running and ready. start, stop, restart, upgrade and uninstall wait for
any other kcap changing the installation, and first finish or undo a setup, upgrade or purge that was interrupted.

upgrade exits 0 when it upgraded, 1 when it failed before the switch, 2 when it failed after the switch, 3
when there was nothing to do, and 4 when no bundle is published for this version yet. fetch exits 0 when the
bundle is in the cache, 1 when it failed, 3 when the installation already runs this version, and 4 when no
bundle is published for it yet. intelligence exits 0 when the server took the answer, 1 when it could not be
asked, and 2 when the arguments or the server refused it, storing nothing.

On Windows the server runs under the kcap-service Windows service when that is installed (`kcap setup
--local --windows-service`, or `kcap daemon service install --system`, moves it there), and otherwise as a
per-user Scheduled Task named kcap-local that runs while you are signed in.

The installation lives in ~/.config/kcap/local, or in KCAP_LOCAL_ROOT when it is set; its logs are
in the logs directory under it. The root must leave room for the stack's sockets: the longest,
data/kurrentdb/kurrent.sock under it, must fit in 103 bytes on macOS (107 on Linux), so setup refuses
a longer root before it installs anything.
